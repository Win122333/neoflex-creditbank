# Микросервис Заявка (Statement)

## 📖 Описание проекта

Микросервис **Statement** является входным шлюзом (API Gateway) кредитного конвейера для взаимодействия с пользователем. Основная задача сервиса — прием первичных заявок на кредит, базовая валидация (прескоринг) и маршрутизация запросов в микросервис **Deal** (Сделка).

### Логика работы:
1. **Создание заявки:** 
   Пользователь отправляет данные в формате `LoanStatementRequestDto` на эндпоинт `/statement`. 
   Микросервис проводит предварительный скоринг (прескоринг). Если проверки пройдены, данные передаются в МС **Deal** через `RestClient`. 
   В ответ возвращается список из 4-х кредитных предложений (`List<LoanOfferDto>`), отсортированных от наименее выгодного к наиболее выгодному.
2. **Выбор предложения:** 
   Пользователь выбирает одно из предложений и отправляет его в формате `LoanOfferDto` на эндпоинт `/statement/offer`. 
   Микросервис перенаправляет этот запрос в МС **Deal** (`/deal/offer/select`) для фиксации выбранных условий.

## 📡 API Микросервиса

Все эндпоинты покрыты документацией Swagger. После запуска сервиса UI доступен по адресу:  
`http://localhost:<port>/swagger-ui/index.html` (порт указывается в `application.yml`).

### 1. Прескоринг и запрос предложений
* **HTTP Метод:** `POST`
* **Эндпоинт:** `/statement`
* **Request:** `LoanStatementRequestDto`
* **Response:** `List<LoanOfferDto>`
* **Описание:** Валидирует входные данные. При успешном прескоринге отправляет запрос в МС Deal, получает 4 оффера, сортирует их по ставке (от большей к меньшей) и возвращает клиенту.

### 2. Выбор кредитного предложения
* **HTTP Метод:** `POST`
* **Эндпоинт:** `/statement/offer`
* **Request:** `LoanOfferDto`
* **Response:** `void` (200 OK)
* **Описание:** Принимает выбранный пользователем оффер и проксирует запрос в МС Deal для дальнейшей обработки и привязки к заявке.
