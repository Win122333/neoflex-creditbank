# Микросервис Калькулятор (Calculator) - MVP 1

## Описание проекта

Микросервис **Calculator** — это вычислительное ядро системы кредитования. Он отвечает за первичную валидацию данных (прескоринг), расчет возможных условий кредита (формирование кредитных предложений) и полный скоринг клиента с детальным расчетом параметров кредита (график платежей, полная стоимость кредита, ставка и ежемесячный платеж).

## Структура DTO

В проекте используются следующие объекты передачи данных (Data Transfer Objects):
* `LoanStatementRequestDto` — входящие данные для первоначального расчета.
* `LoanOfferDto` — исходящее кредитное предложение.
* `ScoringDataDto` — расширенные данные для полного скоринга.
* `CreditDto` — итоговые параметры рассчитанного кредита.
* `EmploymentDto` — данные о трудоустройстве (вложенный объект в ScoringDataDto).
* `PaymentScheduleElementDto` — элемент графика платежей (вложенный объект в CreditDto).

## API Эндпоинты

### 1. Расчет возможных условий кредита
* **Метод:** `POST`
* **URL:** `/calculator/offers`
* **Request Body:** `LoanStatementRequestDto`
* **Response:** `List<LoanOfferDto>`

**Логика работы:**
1. Проводится **прескоринг** входящих данных.
2. Генерируется **4 кредитных предложения** на основе всех возможных комбинаций услуг:
   * Страховка отключена, Зарплатный клиент отключен (`false`, `false`)
   * Страховка отключена, Зарплатный клиент включен (`false`, `true`)
   * Страховка включена, Зарплатный клиент отключен (`true`, `false`)
   * Страховка включена, Зарплатный клиент включен (`true`, `true`)
3. Базовая процентная ставка берется из конфигурационного файла (property).
4. Условия влияют на ставку (например, наличие страховки снижает ставку на 3%, зарплатный проект — на 1%). Стоимость страховки прибавляется к телу кредита.
5. Список предложений сортируется от худшего к лучшему (от самой высокой итоговой ставки к самой низкой).

### 2. Валидация, скоринг и полный расчет параметров
* **Метод:** `POST`
* **URL:** `/calculator/calc`
* **Request Body:** `ScoringDataDto`
* **Response:** `CreditDto`

**Логика работы:**
1. Проводится строгий **скоринг** данных клиента.
2. Вычисляется итоговая процентная ставка (`rate`).
3. Вычисляется полная стоимость кредита (`psk`).
4. Рассчитывается аннуитетный ежемесячный платеж (`monthlyPayment`).
5. Формируется детальный график платежей на весь срок (`List<PaymentScheduleElementDto>`).
6. Возвращается объект `CreditDto` со всеми рассчитанными параметрами.

## Логирование и Документация API

* **Логирование:** 
  * Входные и выходные параметры API логируются на уровне `INFO`.
  * Промежуточные шаги расчетов логируются на уровне `DEBUG`.
* **Документация:**
  * Интегрирован Swagger UI.
  * Все эндпоинты, форматы запросов и ответов задокументированы с помощью аннотаций Springdoc.

---

## Тестирование

* Бизнес-логика микросервиса (сервисный слой, калькуляции, контроллеры) покрыта unit-тестами.
* Процент покрытия кода тестами составляет **≥ 90%**.
* В качестве инструмента для создания заглушек (моков) используется библиотека **Mockito**.

## Правила работы с репозиторием (Git Workflow)

* **Иерархия папок:** `<папка_с_полным_именем_проекта>/calculator`
* Основные ветки: `main` (стабильная) и `develop` (разработка).
* Вся новая разработка ведется в функциональных ветках, отходящих от `develop`.
* Правило именования веток: `feature/<MVP-{номер MVP}>` (например, `feature/MVP-1`).
* Слияние кода происходит строго через **Pull Request** из `feature`-ветки в `develop`.
