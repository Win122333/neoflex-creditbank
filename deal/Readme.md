# Микросервис Сделка (Deal)

## 📖 Описание проекта

Микросервис **Deal** является центральным узлом (ядром) системы кредитного конвейера. Он отвечает за управление процессом оформления кредита, сохранение состояния заявок (Statement), данных клиентов (Client) и параметров кредита (Credit) в базу данных. 

Сервис оркестрирует работу других микросервисов:
* Выполняет синхронные HTTP-запросы к микросервису **Calculator** для получения кредитных предложений и итогового скоринга.
* Асинхронно публикует события в **Apache Kafka** для микросервиса **Dossier**, инициируя отправку email-уведомлений клиенту на различных этапах оформления сделки.

## 📡 API Микросервиса

Все эндпоинты задокументированы через Swagger. Доступ к Swagger UI после запуска: `http://localhost:<port>/swagger-ui/index.html`.

### 1. Первичная заявка и запрос офферов
* **HTTP Метод:** `POST`
* **Эндпоинт:** `/deal/statement`
* **Request:** `LoanStatementRequestDto`
* **Response:** `List<LoanOfferDto>`
* **Описание:** Создает сущности `Client` и `Statement` в БД. Отправляет запрос в Калькулятор (`/calculator/offers`), присваивает полученным офферам ID созданной заявки и возвращает список из 4-х предложений (от худшего к лучшему).

### 2. Выбор кредитного предложения
* **HTTP Метод:** `POST`
* **Эндпоинт:** `/deal/offer/select`
* **Request:** `LoanOfferDto`
* **Response:** `void` (200 OK)
* **Описание:** Находит заявку по `statementId`. Обновляет её статус и историю статусов, сохраняет выбранное предложение (`appliedOffer`) в заявку. Инициирует отправку письма клиенту о необходимости завершить регистрацию.

### 3. Завершение регистрации и полный расчет
* **HTTP Метод:** `POST`
* **Эндпоинт:** `/deal/calculate/{statementId}`
* **Request:** `FinishRegistrationRequestDto`
* **Response:** `void` (200 OK)
* **Описание:** Достает заявку из БД. Формирует `ScoringDataDto` на основе новых и уже имеющихся данных клиента. Отправляет запрос в Калькулятор (`/calculator/calc`). На основе ответа создает сущность `Credit` (со статусом `CALCULATED`), привязывает к заявке и сохраняет в БД. Обновляет статус заявки.

### 4. Работа с документами
* **`POST /deal/document/{statementId}/send`** — Запрос на формирование и отправку документов. Меняет статус заявки и отправляет событие в Kafka.
* **`POST /deal/document/{statementId}/sign`** — Запрос на подписание документов. Генерирует секретный код (SES), сохраняет его в БД и отправляет событие в Kafka для передачи кода клиенту.
* **`POST /deal/document/{statementId}/code`** — Ввод SES-кода клиентом. Сравнивает присланный код с сохраненным в БД. При совпадении меняет статус кредита на `ISSUED`, а статус заявки на `CREDIT_ISSUED`, завершая сделку.

## 📨 Интеграция с Kafka (Producer)

Микросервис **Deal** выступает в роли издателя (Producer) и отправляет сообщения (в формате `EmailMessage`) в микросервис **Dossier** через следующие топики:

* `finish-registration` — Завершение регистрации.
* `create-documents` — Запрос на создание документов.
* `send-documents` — Отправка готовых документов клиенту.
* `send-ses` — Отправка секретного кода для подписания (ПЭП).
* `credit-issued` — Уведомление об успешной выдаче кредита.
* `statement-denied` — Уведомление об отказе (на этапе скоринга).

## 🗄 Структура БД (PostgreSQL)

Сущности реализованы с использованием Spring Data JPA:
* **Client** (Зеленый) — отдельная таблица. Поля `passport` и `employment` сохраняются в формате `jsonb`.
* **Credit** (Зеленый) — отдельная таблица. Содержит параметры кредита и график платежей (`payment_schedule` в формате `jsonb`).
* **Statement** (Зеленый) — отдельная таблица. Связана с Client и Credit. Поля `applied_offer` и `status_history` хранятся в формате `jsonb`.
* **Перечисления (Enums)** (Синий) — `ApplicationStatus`, `CreditStatus` и др. сохраняются в БД как `varchar`.
